# Terraform/OpenTofu provider v2.2.0

## Draft authoring and execution

The `platform-orchestrator_module_draft` resource manages editable Drafts and
retained revisions. Its `authoring_key` makes creation retry-safe. Publication
freezes the selected revision as a separate immutable Proposed Version and
closes the Draft. Create another Draft to continue authoring. Destroy closes an
open Draft while retaining its history.

The `platform-orchestrator_module_draft_test` resource captures an immutable
snapshot for the selected Project and Environment. Select it explicitly through
a deployment's `draft_test_snapshots`. Saving or editing a Draft does not
capture or deploy a test. Editing preserves the Draft identity, earlier
snapshots, and deployment results. Unchanged reviewed configuration produces an
empty plan.

Resource Types retain their identity and gain immutable, consecutive interface
versions. Data sources expose exact interfaces and history. Importing a Module
Version preserves its selected interface in provider state; existing Versions
and Pins keep their original binding.

## Compatibility and upgrade

The provider embeds generated API clients for the Control Plane and Data Plane.
Use matching server APIs and gateway routes. Existing HTTP operations remain
available. Older servers that lack a requested endpoint return a clear error.
An explicit Draft test never falls back to an ordinary deployment or a
published Default.

Back up state and review the plan before applying the provider upgrade. Upgrade
compatible server schemas before enabling the new workflows. Older server
binaries refuse the new schemas; keep the compatible schema and recover with
compatible images or a forward fix.
