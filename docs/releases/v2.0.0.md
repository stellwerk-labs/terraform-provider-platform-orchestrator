# Terraform/OpenTofu provider v2.0.0

This release changes Module and Resource Type authoring.
Back up state and review a full plan before migrating an existing configuration.

## What changes

- Separate Module catalogue identity from immutable version publication.
- Publish complete Proposed versions with explicit output declarations and manage
  lifecycle ownership separately from observation.
- Expose version/history-related reads, exact Pins, frozen bulk Pin operations,
  append-only notes and atomic multi-Module lifecycle transactions.
- Reject Resource Type contract mutation locally, including against older servers.
- Retain published versions on removal from Terraform state and archive catalogue
  entries whose history prevents deletion.
- Normalize imported version definitions so a duplicated semantic-version field
  does not cause a spurious replacement plan.

## Breaking changes and migration

The legacy mutable Module resource does not model immutable catalogue/version
ownership. Transfer state to catalogue entries without deleting the underlying
Module, then publish new versions explicitly. Import retained versions rather
than trying to republish their reserved identities.

Resource Types are immutable. A changed contract requires a new Resource Type
and Module binding. New Module publications must include the exact output schema
of a Resource Type whose output schema is nonempty.

An external source revision is required; an external artifact digest is optional.
A supplied digest remains an immutable claim, not verification. Inline source must
omit it. Do not invent metadata for retained legacy versions.

Omit lifecycle ownership when another client controls promotion. Otherwise a
historical resource declaring Default can ask Terraform to restore it after a
later promotion. Use fixed reviewed expected revisions for lifecycle receipts.

Published version deletion removes Terraform ownership only. Referenced providers
and Resource Types may require explicit retention; retention does not revoke
credentials or remove infrastructure. Destroy Environments before their Runner.

Follow [the upgrade guide](https://github.com/stellwerk-labs/terraform-provider-platform-orchestrator/blob/v2.0.0/docs/guides/module-management-upgrade.md) for state
transfer, import, lifecycle ownership and teardown. Never discard state to hide
an unsuccessful destroy.

## Compatibility and distribution

Use CP 3.0.0, DP 3.2.0 and IAM 2.4.0.
Test both Terraform and OpenTofu with the exact provider version, without local
development overrides, after distribution.

This release includes platform ZIPs, registry metadata, SHA-256 checksums and
the detached GPG checksum signature. Terraform and OpenTofu use the same provider
release through their respective registries.
