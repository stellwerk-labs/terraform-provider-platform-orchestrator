# Terraform provider 2.4.0

Destroying a managed Provider with `deletion_policy = "delete"` accepts
`202 Accepted` and polls the normal Control Plane endpoint until removal is
confirmed by `404`. Provider configuration remains available to managed resources
and in-flight operations during retirement. The resource and data source expose
`deletion_requested_at`, and the resource supports a configurable delete timeout.

A timeout or pending cleanup retains Terraform ownership and configuration so a
later destroy can continue. It does not claim deletion succeeded or silently
drop state. `deletion_policy = "retain"` continues to remove only Terraform
ownership without requesting server retirement; import the retained Provider
before managing it again.

Use the compatible published Control Plane API from the coordinated
Provider-retirement release. This change creates no cloud resources and does
not relax normal cleanup or authorization checks.

Release tooling and binary qualification require Go 1.26.11.

Release binaries retain function symbols while omitting DWARF debugging data so
security checks can identify linked vulnerable functions precisely. Every
archive must pass the pinned binary scanner before SBOM generation and signing;
stripped executables are rejected. Application dependencies are unchanged.
