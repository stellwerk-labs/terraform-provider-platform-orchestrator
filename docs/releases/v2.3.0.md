# Terraform/OpenTofu provider 2.3.0

## Shared Runner capacity and protocols

Add optional `runner_configuration.max_parallel_jobs` and
`runner_configuration.supported_protocols` to all five Runner resources and
corresponding data sources: Kubernetes, GKE, EKS, Kubernetes agent and serverless
ECS. Existing family-specific cluster, authentication, job and state-storage
configuration remains unchanged.

`max_parallel_jobs` must be positive and limits concurrent jobs across all
Environments sharing a Runner. An unset limit retains legacy unlimited behavior.
Reducing a limit lets already admitted work drain before new admission.

`supported_protocols` is a set of at most 16 unique names, each 1 to 128
characters. An empty set explicitly declares no protocols. Read-only observations
require `environment-observation/v1`, a positive capacity limit and an installed
Runner executable that actually implements the protocol. Declaring a protocol
does not upgrade the executable or enable an observation service.

## Ownership and updates

Omitting either setting preserves existing Orchestrator configuration, including
on import. Terraform treats an explicit `null` and omission equivalently. Once
Terraform has actually managed a setting, removing it or setting it to `null`
clears that setting through the API. Before ownership has been established,
omission or `null` preserves the operator's value instead.

A same-value no-op against an imported or operator-managed value does not
establish Terraform ownership. Apply a real configured update to start managing
it. Review the full Terraform/OpenTofu plan before changing or removing settings.
Data sources report the server's current values without claiming ownership.

## Compatibility and upgrade

Use the matching qualified Orchestrator release set: Control Plane 3.3.0, Data
Plane 4.2.1, IAM 2.6.0 and Runner 3.2.0. The provider's Control Plane API snapshot
is pinned to the independently published shared/v3.1.0 source. A published SDK
alone does not add this behavior to an older server.

These are generic Runner settings. Installing the provider does not install,
enable or license a separately distributed plugin. Existing Runner configurations
can omit both attributes. Schema and conversion coverage across five families
does not establish live execution coverage for every compute and storage
combination; qualify the deployment combination you operate.
