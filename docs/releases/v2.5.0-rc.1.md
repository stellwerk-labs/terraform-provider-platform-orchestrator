# Terraform Provider 2.5.0-rc.1

Manage project pipelines with separate resources for draft documents, immutable published versions and forward/rollback policy. Drafts accept canonical JSON, with YAML supported through `jsonencode(yamldecode(file(...)))`. Revision checks reject concurrent edits. Publication uses an exact reviewed draft revision and a stable request key; publishing does not automatically allow or select the version in policy.

Deployment resources accept `pipeline_version_id` for an exact published version. Omission uses the server's default, preserving existing deployments on upgrade. Changing the selection starts a new deployment. It does not edit a recipe or approve its gates. The server enforces current policy, Runner compatibility and executable identity.

Native Agent resources and data sources use the server-issued immutable UUID and approved public catalogue. Private site configuration remains local. Registration does not activate or assign a site; its history is retained and destroy is refused. Clearing inventory disables new admission without cancelling accepted work.

A conclusively successful deployment remains successful when its encrypted outputs cannot yet be retrieved. The Provider records a warning and retains the deployment without taint; an authorized refresh can retrieve outputs later without redeploying. Protect Terraform state because retained private output metadata contains encryption material. A create error can still leave Terraform taint, and termination before state is saved can lose output custody. Verify the accepted deployment before another Apply.

Use the coordinated Core, Data Plane, IAM and Runner candidates with Terraform or OpenTofu. Native execution requires the documented site activation, durable PostgreSQL, trust and state-storage prerequisites.
