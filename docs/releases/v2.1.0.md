# Terraform/OpenTofu provider v2.1.0

This version adds deployment queue controls and organisation plugin enablement.
Existing configuration and state require no schema migration, but busy
Environment applies change behaviour as described below.

## Deployment behaviour and upgrade actions

- `platform-orchestrator_deployment.when_busy` accepts `queue` or `reject`.
  For `mode = "deploy"`, unset means `queue`, also the Data Plane's new
  default. The provider explicitly sends either value. There is no schema
  default, so existing state does not gain a default-driven plan change.
- An apply that previously failed immediately on a busy Environment now waits
  within its create timeout. Set `when_busy = "reject"` to keep fail-fast
  behaviour. Organisation-token requests cannot queue and still fail with
  `environment_busy`.
- Optional `halt_on_failure` has no schema default; unset means `false`.
  When true, a queued deploy does not start after the Deployment it waited
  for fails. The apply names that Deployment with
  `previous_deployment_failed`. Combining it with `when_busy = "reject"`
  is refused at planning.
- Create and update timeouts default to 20 minutes and cover the request,
  queue wait and, when requested with `wait_for`, Deployment completion.
  A request still queued at timeout is cancelled. Changing only
  `when_busy`, `halt_on_failure` or timeouts updates state without redeploying.
- `plan_only` never queues. It may start while requests are queued, but not
  beside another running Deployment in that Environment. Plan diagnostics
  warn when running or queued Deployments can change the result.
- Refusals explain queue exclusions, Environment fences, the fencing Deployment
  and when an operator can use `acknowledge-outcome`.

## Organisation plugin enablement

The new `platform-orchestrator_plugin_enablement` resource enables an
installation for the provider's organisation. Destroy disables the enablement;
it does not delete its record. The
`platform-orchestrator_plugin_installation` data source reads installation
status, organisation mode/defaults, enabled and pending organisations,
capability registration and covering licence grants.

Installation and identity setup remain platform operator tasks through
`octl plugin-manager`. Identities are IAM platform principals belonging to
no organisation, so an installation can serve every organisation enabled for it.
The provider does not manage installation-wide organisation mode or identities.

In mode `all`, the Orchestrator enables organisations itself. The resource
adopts an existing enablement without writing when its configured settings
already hold; explicit settings replace Orchestrator defaults. Destroy is the
organisation's opt-out, which the Orchestrator does not undo. Enabling beyond
the installation-wide licence grant's organisation limit fails with
`plugin_organization_limit` and a remedy.

The plugin contract is `v1alpha` and supports only first-party Stellwerk plugins.
An installation's enabled organisations share the plugin's own database, while
the Orchestrator enforces organisation scope on each effect. Install only
reviewed packages. Plugin packages are distributed separately from the
Orchestrator and this provider.

## Other changes

- Optional private CA bundle for API servers using a private certificate authority.
- Module Version coordinates retain their canonical identity.

## Upgrade and recovery

Back up Terraform/OpenTofu state and configuration before upgrading. Review
create/update timeouts and use explicit `when_busy = "reject"` where automation
requires immediate failure on a busy Environment. Refresh and inspect the plan
before applying.

For coordinated server upgrades, retain additive database migrations. After
new-schema writes, recover with a reviewed compatible application revision or
forward repair rather than old writers or database Down migrations. Restore
state only with a recovery plan that also accounts for server-side effects.

## Compatibility and distribution

The target compatible server set is CP 3.1.0, DP 4.0.0 and IAM 2.5.0.
Verify the selected artifacts and coordinated set before upgrading.
Select provider version 2.1.0 in Terraform or OpenTofu. The two registries
index releases independently, so check availability in the registry you use.
